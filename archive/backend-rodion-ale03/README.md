# Simracing Setups — Backend

Бэкенд MVP сервиса рекомендаций по настройке автомобиля для симрейсинга. Пользователь описывает поведение машины через структурированную форму, а API подбирает подходящие **экспертные правила** и возвращает рекомендации по изменению параметров сетапа.

Поиск **детерминированный**: в текущей версии не используются ML-модели или LLM. Рекомендации формируются на основе правил, сохранённых в SQLite.

## Технологии

- **Python** — язык разработки (локальная проверка выполнена на Python 3.14.7).
- **FastAPI** — REST API и Swagger UI.
- **Pydantic** — валидация входных данных и схемы ответов.
- **SQLAlchemy** — ORM и работа с базой данных.
- **SQLite** — хранение параметров, правил и пользовательских запросов.
- **Pytest** и **FastAPI TestClient** — автоматическое тестирование.

## Возможности MVP

- Проверка состояния сервиса (`GET /health`).
- Получение рекомендаций по шести полям формы (`POST /api/v1/recommendations`).
- Поиск по типу проблемы, фазе поворота и, при наличии, моменту заезда.
- Проверка применимости правила к выбранным автомобилю и трассе.
- Исключение правил, которые не разрешены к выдаче (`draft_not_allowed`).
- Ответы `match` и `no_match` с уникальным `request_id`.
- Сохранение пользовательских обращений и идентификаторов выданных правил в SQLite.
- Обработка ошибок валидации (HTTP 400) и внутренних ошибок (HTTP 500).
- CORS для согласованных адресов фронтенда.

> **Важно:** выдаются только правила со статусом `verified`. Тестовое правило `TEST-001` используется исключительно для локальной проверки и не должно оставаться в рабочей базе при публикации MVP.

Архитектура разделена на уровни:

```text
HTTP-клиент → Router → Service → Repository → SQLite
```

`Router` обрабатывает HTTP-запрос и формирует ответ; `Service` реализует бизнес-логику; `Repository` выполняет операции с базой данных.

## Локальный запуск

Команды выполняются **из корневой директории проекта**.

### 1. Создать и активировать виртуальное окружение

Linux/macOS:

```bash
python -m venv venv
source venv/bin/activate
```

Windows (PowerShell):

```powershell
py -m venv venv
.\venv\Scripts\Activate.ps1
```

### 2. Установить зависимости

```bash
python -m pip install -r requirements.txt
```

### 3. Создать таблицы SQLite

```bash
python -m app.db.init_db
```

В текущей конфигурации используется локальная база `simracing.db` (SQLite). Файл создаётся в рабочей директории, из которой запускается приложение.

> `Base.metadata.create_all()` создаёт отсутствующие таблицы, но **не изменяет структуру уже существующих**. При изменении моделей нужно отдельно управлять миграциями либо пересоздавать тестовую БД, если данные не нужны.

### 4. Запустить сервер

```bash
python -m uvicorn main:app --reload
```

После запуска доступны:

- **API:** <http://127.0.0.1:8000>
- **Swagger UI:** <http://127.0.0.1:8000/docs>
- **OpenAPI JSON:** <http://127.0.0.1:8000/openapi.json>
- **Проверка состояния:** <http://127.0.0.1:8000/health>

## API

### `GET /health`

Проверяет, что HTTP-сервис отвечает.

**Ответ — HTTP 200:**

```json
{
  "status": "ok"
}
```

### `POST /api/v1/recommendations`

Получает данные формы, ищет подходящие экспертные правила, записывает обращение в базу и возвращает результат.

**Тело запроса:**

| Поле | Тип | Обязательное | Описание |
| --- | --- | --- | --- |
| `car` | `string` | Да | Название автомобиля |
| `track` | `string` | Да | Название трассы |
| `symptom_type` | `"understeer" \| "oversteer"` | Да | Недостаточная или избыточная поворачиваемость |
| `corner_phase` | `"entry" \| "mid" \| "exit"` | Да | Фаза поворота: вход, середина или выход |
| `comment` | `string` | Да | Комментарий пользователя, от 3 до 500 символов |
| `stint_moment` | `"from_start" \| "after_laps" \| null` | Нет | Когда возникает проблема; по умолчанию `null` |

`comment` сохраняется в истории запросов, но **не используется для подбора правил**. Сейчас `car` и `track` принимаются как строки; при согласовании окончательного справочника допустимых значений их валидацию нужно дополнить.

**Пример запроса:**

```bash
curl -X POST http://127.0.0.1:8000/api/v1/recommendations \
  -H "Content-Type: application/json" \
  -d '{
    "car": "NASCAR Cup Series Next Gen (Gen 7)",
    "track": "Daytona International Speedway",
    "symptom_type": "understeer",
    "corner_phase": "entry",
    "comment": "Машина плохо поворачивает на входе",
    "stint_moment": "from_start"
  }'
```

#### Совпадение найдено — HTTP 200 (`match`)

Пример структуры ответа **при наличии соответствующего тестового правила**:

```json
{
  "status": "match",
  "request_id": "ea9cedee-9e9b-45c8-9713-a478a16667f7",
  "recommendations": [
    {
      "rule_id": "TEST-001",
      "parameter": "front_brake_bias_pct",
      "direction": "decrease",
      "change_description": "Тестовое изменение параметра",
      "expected_effect": "Тестовый ожидаемый эффект",
      "limitations": "Только для проверки API",
      "basis": "TEST"
    }
  ]
}
```

`direction` может принимать значения `increase` или `decrease`.

#### Совпадений нет — HTTP 200 (`no_match`)

```json
{
  "status": "no_match",
  "request_id": "d4d7b398-a61e-4faf-bac2-367d9ce7a834",
  "message": "Подходящее правило не найдено."
}
```

В ответе `no_match` поле `recommendations` отсутствует.

#### Ошибка входных данных — HTTP 400

```json
{
  "status": "error",
  "error": {
    "code": "validation_error",
    "message": "Проверьте заполнение полей",
    "fields": {
      "comment": "String should have at least 3 characters"
    }
  }
}
```

В отличие от стандартного поведения FastAPI, ошибки валидации тела запроса возвращают **HTTP 400**, а не 422. Описания ошибок конкретных полей могут быть на английском, так как поступают от Pydantic.

#### Внутренняя ошибка — HTTP 500

```json
{
  "status": "error",
  "error": {
    "code": "internal_error",
    "message": "Внутренняя ошибка сервера"
  }
}
```

Технические детали исключения записываются в лог сервера и не передаются клиенту.

## Как подбираются рекомендации

1. API валидирует шесть полей входного запроса.
2. Репозиторий выбирает правила по `symptom_type` и `corner_phase` со статусом `verified`.
3. Если указан `stint_moment`, учитываются правила с соответствующим значением или с `null` (без ограничения по моменту).
4. Сервис проверяет, что `car` и `track` перечислены в `applicability` правила.
5. Подходящие правила возвращаются в устойчивом порядке; пустой результат даёт `no_match`.
6. В SQLite сохраняются входные поля, `request_id`, итоговый статус и список `rule_ids`.

Правила со статусом `draft_not_allowed` в рекомендации не включаются. Пустой список трасс в `applicability` не означает применимость ко всем трассам.

## База данных

Основные SQLAlchemy-модели:

| Модель | Назначение |
| --- | --- |
| `Parameter` | Настраиваемый параметр автомобиля и его описание |
| `Rule` | Экспертное правило, условия применимости и ожидаемый эффект |
| `Requests` | История обращений к API с результатом поиска |

`Rule` связан с `Parameter` через внешний ключ. В истории обращения сохраняется `request_id` (UUID), поэтому результат API можно сопоставить с записью в базе.

В текущей реализации у модели `Requests` имя SQL-таблицы — **`request`** (в единственном числе).

Пример просмотра обращений:

```bash
sqlite3 simracing.db \
  'SELECT request_id, status, rule_ids, comment FROM request;'
```

Для результата `no_match` сохраняется пустой список `rule_ids`: `[]`.

## CORS

Разрешённые источники фронтенда:

- `https://kom1sh.github.io`
- `http://localhost:5173`
- `http://localhost:4173`

Разрешённые методы: `GET`, `POST`.

Проверка preflight-запроса:

```bash
curl -i -X OPTIONS http://127.0.0.1:8000/api/v1/recommendations \
  -H "Origin: https://kom1sh.github.io" \
  -H "Access-Control-Request-Method: POST"
```

Ожидается HTTP 200 и заголовок `access-control-allow-origin: https://kom1sh.github.io`.

> CORS не публикует сервер в интернете. Чтобы фронтенд на GitHub Pages работал у других пользователей, ему потребуется доступный извне HTTPS-адрес развёрнутого API.

## Тестирование

Запуск всех тестов:

```bash
python -m pytest -v
```

Запуск только API-тестов:

```bash
python -m pytest tests/test_recommendations_api.py -v
```

Последний локальный результат: **22 passed, 1 warning** (19 октября 2026 г.). Предупреждение относится к устаревающему использованию `httpx` через Starlette `TestClient`; прохождению тестов оно не препятствует.

Тесты покрывают репозитории, поиск рекомендаций, `match` / `no_match`, сохранение обращений, HTTP 400/500, исключение черновых правил и CORS. Для API-тестов используется отдельная SQLite **в памяти**, которая не изменяет `simracing.db`.

## Ограничения текущей версии

- Рекомендации формируются только на основе подготовленных экспертных правил, без ML и LLM.
- Поддерживаются только сценарии, предусмотренные содержимым базы правил.
- Для `car` и `track` ещё требуется окончательное согласование допустимых значений со справочником команды.
- Для корректной выдачи нужны правила со статусом `verified` и заполненными списками применимых автомобилей и трасс.
- Изменения структуры существующей базы данных не выполняются автоматически.
- Перед публикацией следует убрать демонстрационные записи, в частности `TEST-001`, и убедиться, что правила разрешены к выдаче.
